# QuickConnect repository instructions

## Stage

This package is a product blueprint. Future implementation starts with an owner-accepted milestone plan. Read README.md, docs/DECISIONS.md, and the relevant domain document before changing scope.

## Product boundaries

QuickConnect organizes permitted professional contacts, explains relevance, prepares honest introductions, and tracks relationships. Do not replace approved source adapters with scraping or assume OAuth login grants invitation access.

Use synthetic people and messages in development. Keep personal contacts, CSVs, notes, database dumps, and credentials out of public Git.

## Facts and state

Preserve provenance, freshness, and uncertainty. Required criteria do not pass unknown facts. Company vacancies do not prove a person is hiring. Model output is a draft, not a source of new facts.

Copied is not sent. Self-reported sent is not confirmed delivery. Notification delivery is separate from follow-up completion.

## Engineering workflow

Use isolated branches/worktrees for concurrent bounded tasks. Assign one owner for shared contracts. Keep database test state isolated.

Make coherent focused commits with relevant verification. Record actual checks and limitations. Independent validation references a specific commit.

The hierarchy describes future responsibilities; it does not require spawning agents for every task. Delegate only when authorized and useful.

## Authority

Server authorization applies to every workspace-owned object, derived result, export, import, and job. User review of one draft does not authorize future messages.

Do not implement external sending, change source terms, publish personal data, merge, or release based only on this plan.
